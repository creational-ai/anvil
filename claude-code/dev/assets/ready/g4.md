# G4 — Ready for plan review?

> A concrete gate profile. It fills the slot contract defined in `references/ready-guide.md` and **inherits** the 7-step flow, the five leashes, and the autonomy check from that base. It does **not** restate the flow. The `/dev-ready` command binds this profile when the resolved break is G4 (a `…-plan.md` exists; its `…-plan-review.md` twin does **not** yet — the twin would advance the cursor to G5).

**Break**: `/dev-plan` → **[G4]** → `/review-doc`

The plan exists; the question is whether it is *worth* a `/review-doc` pass and, above all, whether **every step is autonomous**. G4 is the load-bearing autonomy gate — it is the one break where executable steps exist to verify, so the smell test (G1–G3) becomes a per-step verdict here.

---

## Required slots

### inputs

- `docs/[milestone-slug]-[task-slug]-plan.md` — the one artifact for this break.
- No `-review.md` twin yet (if a `…-plan-review.md` exists, the cursor has advanced to G5 — the resolver binds that profile instead; to re-check G4, run `/dev-ready` against a plan with no review twin).

### rubric (the fixed checklist — G4's identity)

Walk these inline, in order, against the plan only:

1. **Every step autonomous** *(load-bearing — the core G4 verdict)*. For **each** implementation step, the executor must be able to carry it with **no exploration turn (spike)** and **no human turn (go-ahead / operator-driven step)**. The three exclusions must not appear in any step **as work**:
   - a step whose body is "spike / figure out / investigate which …" → **not autonomous**.
   - a step that says "ask the operator / wait for approval / confirm with the user before proceeding" → **not autonomous**.
   - an operator-driven step (the operator must perform an action mid-step) → **not autonomous**.
   - *Hatch closed*: validation that genuinely needs a human or live environment is permitted **only** as a labeled, bounded **post-execution acceptance activity**. If a step relabels real exploratory/decision work as "acceptance" to slip past, treat it as non-autonomous and **withhold READY**.
2. **Step sizing** — each step is bite-sized: small, completable, independently testable. A step that bundles several unrelated changes should be flagged for splitting (a short in-scope action, not a re-architecture).
3. **Acceptance criteria** — each step states what "done" means (an explicit, checkable criterion), so the executor has a self-check.
4. **Self-containment** — each step names the files it creates/modifies and the patterns/constraints to follow; the executor does not have to leave the step to know what to build.
5. **Test scope** — each step's verification is intentional and scoped (what is being tested, and how), per the environment's conventions.

> The autonomy check (#1) is the gate's reason to exist; the remaining four are the **existing plan checks** the plan template already implies. G4 verifies them — it does **not** re-run `/review-doc`'s deep soundness/template-alignment pass (that is the review layer's job, one step downstream).

### verdict semantics

- **READY** = **ready-for-`/review-doc`** — every step is autonomous and the plan checks pass; the plan is worth a review pass and downstream `/dev-execute-run` will be autonomous end-to-end.
- **NOT-READY** = at least one step is non-autonomous or fails a plan check; emit the **shortest in-scope action list** (e.g., "split Step N into N-a/N-b," "resolve the spike in Step N before planning it as a step," "add an acceptance criterion to Step M").
- **escalate: re-scope** = the path to ready is a sprawl (many steps non-autonomous, or the plan's whole shape forces non-autonomous work) rather than a short diff.

## Tunable slots

### allowed remedy classes

Default — **doc-edit / spike / scope-out / escalate**. No override (G4 uses the base default; only G3 extends it with *archive / don't-plan*).

- **doc-edit** — tighten a step in place (add acceptance criteria, split a step, scope its tests).
- **spike** — a flagged non-autonomous "figure out X" step should be **resolved before planning** (do the spike, then plan the now-known work as autonomous steps) — not carried into the plan as a step.
- **scope-out** — defer an out-of-scope step to a later task.
- **escalate** — when ready is a sprawl, hand back "escalate: re-scope."

## Notes

- **Depth**: G4 is where the shared autonomy *concern* becomes a **per-step verdict** (executable steps exist here). G1–G3 run the lighter smell test; G5 runs the end-to-end pass over plan + review twin.
- **No weight slot**: G4 runs **inline** like every gate — one agent, one context, the rubric above. Its depth comes from *the inputs existing* (a plan with steps to verify), not from a tunable knob.
- **Bias to READY**: a cosmetic nit in a step (wording, ordering of a checklist) is "nit — proceed," not a block. Block only on a genuine autonomy or plan-check break.
