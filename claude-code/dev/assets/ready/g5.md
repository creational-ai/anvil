# G5 — Ready to execute?

> A concrete gate profile. It fills the slot contract defined in `references/ready-guide.md` and **inherits** the 7-step flow, the five leashes, and the autonomy check from that base. It does **not** restate the flow. The `/dev-ready` command binds this profile when the resolved break is G5 (a `…-plan.md` **and** its `…-plan-review.md` twin both exist — the review twin has advanced the cursor from G4 to G5).

**Break**: `/review-doc` → **[G5]** → `/dev-execute-run`

The plan has been reviewed; this is the **last gate before execution**. The question is whether the plan + its review are cohesive and the whole thing is **fully autonomous end-to-end** — so `/dev-execute-run` can carry it without an exploration turn, a human-gate, or a missing pre-condition surfacing mid-run.

---

## Required slots

### inputs

- `docs/[milestone-slug]-[task-slug]-plan.md` — the reviewed plan.
- `docs/[milestone-slug]-[task-slug]-plan-review.md` — its review twin (its presence is what advanced the cursor to G5). G5 reads **both**.

### rubric (the fixed checklist — G5's identity)

Walk these inline, in order, against the plan + its review twin:

1. **Steps + reviews cohesive.** The `/review-doc` findings on the plan are resolved (or consciously accepted), and the plan still reads as one coherent sequence after those resolutions — no finding left the plan internally inconsistent (e.g., a step split in review that the rest of the plan no longer references correctly).
2. **Fully autonomous end-to-end** *(the load-bearing G5 verdict — end-to-end pass)*. Across **all** steps as a sequence, the executor can run start to finish with **no exploration turn (spike)** and **no human turn (go-ahead / operator-driven step)**. Where G4 verified each step in isolation, G5 verifies the **whole run is autonomous as a chain** — including that no review-introduced change reopened an autonomy gap. The three exclusions (spike / human-gate / operator-driven step) must not appear anywhere in the run as work; labeled, bounded post-execution acceptance activities are the only permitted human/live-environment touch, and if real work hides behind that label, **withhold READY**.
3. **Deploy / pre-conditions present.** The plan names the deploy/verify path and any pre-conditions the run depends on (environment, dependencies, prior-task outputs) — so the run does not stall on a missing precondition the plan assumed but never stated.

> G5 verifies the plan is *executable end-to-end as reviewed* — it does **not** re-run `/review-doc`'s deep pass (already done — its twin is an input). It is the cohesion-plus-end-to-end-autonomy-plus-preconditions check that stands between a reviewed plan and `/dev-execute-run`.

### verdict semantics

- **READY** = **ready-to-execute** — plan + review cohesive, fully autonomous end-to-end, deploy/pre-conditions present; proceed to `/dev-execute-run`.
- **NOT-READY** = a review finding left the plan incoherent, an autonomy gap exists end-to-end, or a deploy/pre-condition is missing; emit the **shortest in-scope action list** (e.g., "reconcile Step 3 split with the Step 5 reference," "state the deploy step's pre-condition," "resolve the residual spike in Step 4").
- **escalate: re-scope** = the path to ready is a sprawl (the plan needs broad rework, not a short diff) — hand back to re-scope.

---

## Tunable slots

### allowed remedy classes

Default — **doc-edit / spike / scope-out / escalate**. No override (G5 uses the base default; only G3 extends it with *archive / don't-plan*).

- **doc-edit** — reconcile a cohesion gap or add a missing pre-condition/deploy note in place.
- **spike** — a residual non-autonomous "figure out X" left after review should be resolved before executing, not carried into the run.
- **scope-out** — defer an out-of-scope step to a later task so the run is self-contained.
- **escalate** — when ready is a sprawl, hand back "escalate: re-scope."

## Notes

- **The end-to-end gate**: G5 is where the autonomy concern becomes an **end-to-end pass over the chain** (plan + review twin), not the per-step verdict G4 ran. It is the last gate before execution, so its job is to confirm the *whole run* is autonomous and pre-conditioned, including that no review-introduced edit reopened a gap.
- **Reads the review twin**: G5's inputs include the `…-plan-review.md` twin (whose presence resolved the cursor here). It checks findings are *resolved and cohesive*, not re-scores them — `/review-doc` already did the deep pass.
- **No weight slot**: G5 runs **inline** like every gate. Its depth (an end-to-end pass) follows from the inputs existing (a reviewed plan with steps and a review twin), not from a tunable knob.
- **Bias to READY**: a cosmetic inconsistency that does not break the run is "nit — proceed." Block only on a genuine end-to-end autonomy gap, an incoherence a review finding left behind, or a missing pre-condition the run depends on.
