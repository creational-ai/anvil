# G1 — Ready to design?

> A concrete gate profile. It fills the slot contract defined in `references/ready-guide.md` and **inherits** the 7-step flow, the five leashes, and the autonomy check from that base. It does **not** restate the flow. The `/dev-ready` command binds this profile when the resolved break is G1 (no `…-design.md` exists yet — G1 is the floor of the artifact ladder).

**Break**: `/dev-usecases` → **[G1]** → `/dev-design`

This is the **lightest** gate and the only one that is a **de-risking judgment, not a document check**. It asks one thing: *have the high-risk issues that would shape the design been de-risked, so the next phase lands grounded and concise?* There is no design artifact to score yet — so G1 makes a call, it does not audit a doc.

---

## Required slots

### inputs

- **Optional** — any de-risking evidence that already exists: a `docs/[milestone-slug]-[task-slug]-usecases.md` (its **goals-at-a-glance** table and per-use-case **extensions** tables are the raw material the rubric reads), freeform operator notes, or a prior spike's output. Evidence is read **if present** under whatever name it has — a retired Stage-0 doc still counts as evidence here even though it is no longer a valid `/dev-ready` argument.
- **No new artifact**. G1 introduces **no `-spike.md` doc-type or convention** — it judges the de-risking *outcome*, not a form. If no de-risking material exists on disk, G1 makes the call **interactively** with the operator (it is inline and light).

### rubric (the fixed checklist — G1's identity)

The lightest rubric — a ~3-item de-risking judgment, run as a smell test (no executable steps or design exist to verify):

1. **Goal clear.** The thing being designed has a stated, understood objective — the operator can say what "done" means at a high level.
2. **High-risk issues de-risked** *(the load-bearing G1 question)*. The unknowns that would **shape the design** — the ones that, if wrong, force a redesign — have been resolved enough that the design will land grounded and concise. This is a judgment about *de-risking outcome*, not a count of documents.
3. **Materials sufficient to design.** Whatever the design phase needs to proceed (constraints, context, prior art) is on hand or knowable without an exploration detour.

> The autonomy check applies here only as the lightest smell test — *"does the goal obviously force an exploration turn before design can even start?"* — not a per-step verdict (no steps exist yet). Depth is shallow by design: the inputs to verify do not yet exist.

### verdict semantics

- **READY** = **proceed-to-design** — the high-risk issues are de-risked; design will land grounded and concise. Proceed to `/dev-design`.
- **NOT-READY** = **spike-first** — a high-risk unknown that would shape the design is unresolved; emit the **shortest in-scope action list** naming what to de-risk before designing (e.g., "resolve which API the integration targets before designing the adapter").
- **escalate: re-scope** = the goal itself is unclear or the de-risking is a sprawl rather than a short spike — hand back to re-scope the goal.

---

## Tunable slots

### allowed remedy classes

Default — **doc-edit / spike / scope-out / escalate**. No override (G1 uses the base default).

- **spike** — the primary G1 remedy: a high-risk unknown should be **resolved before designing**, not carried into the design as an open question. (Resolving it produces de-risking evidence — a note, a prototype outcome — but **no new doc-type**.)
- **doc-edit** — tighten the usecases/notes in place if the gap is a clarity nit rather than a real unknown.
- **scope-out** — defer a high-risk sub-area to a later task so the current design lands concise.
- **escalate** — when the goal is unclear or de-risking is a sprawl, hand back "escalate: re-scope."

---

## Notes

- **Lightest gate**: G1 is a ~3-item de-risking *judgment*. It does not score a design (none exists), re-run any review, or introduce an artifact. Its whole job is to keep the next phase grounded — *spike-first* when a shaping unknown is open, *proceed-to-design* otherwise.
- **No new artifact**: de-risking evidence is read if present (usecases doc / freeform notes / prior spike output), under any name; G1 introduces **no `-spike.md` convention**. The judgment is function, not form.
- **No weight slot**: G1 runs **inline** like every gate. Its depth is shallow because the inputs to verify (a design, executable steps) do not exist yet — not because of a tunable knob.
- **Bias to READY**: a vague phrasing in the goal that is still understandable is "nit — proceed." Block (spike-first) only on a genuine *shaping* unknown that would force a redesign if guessed wrong.
