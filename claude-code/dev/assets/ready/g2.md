# G2 — Ready for design review?

> A concrete gate profile. It fills the slot contract defined in `references/ready-guide.md` and **inherits** the 7-step flow, the five leashes, and the autonomy check from that base. It does **not** restate the flow. The `/dev-ready` command binds this profile when the resolved break is G2 (a `…-design.md` exists; its `…-design-review.md` twin does **not** yet — the twin would advance the cursor to G3).

**Break**: `/dev-design` → **[G2]** → `/review-doc`

The design exists; the question is whether it is **complete and self-contained enough to be _worth_ a `/review-doc` pass**. G2 is **readiness triage, not a second review** — it does not re-score the design's soundness or template-alignment in depth. That deep pass is `/review-doc`'s job, one step downstream; re-checking it here would duplicate the review layer.

---

## Required slots

### inputs

- `docs/[milestone-slug]-[task-slug]-design.md` — the one artifact for this break.
- No `-review.md` twin yet (if a `…-design-review.md` exists, the cursor has advanced to G3 — the resolver binds that profile instead; to re-check G2, run `/dev-ready` against a design with no review twin).

### rubric (the fixed checklist — G2's identity)

Walk these inline, in order, against the design only — as **triage**, not a deep re-score:

1. **Worth reviewing — completeness/self-containment triage** *(the core G2 question)*. Is the design complete and self-contained enough that a `/review-doc` pass would be productive? A design with gaping holes (no proposed approach, undefined scope, a TODO where the analysis should be) is **not yet worth** a review pass — fix the hole first. This is a *readiness* check ("is there enough here to review?"), **not** a soundness re-score ("is the analysis correct?" — that is `/review-doc`'s job).
2. **Autonomy smell test** *(light)*. *"Does the design obviously force non-autonomous work?"* — does it bake in a spike, a human-gate, or an operator-driven step as the core approach? This is the **light** smell test, **distinct from G4's load-bearing per-step verdict** (no executable steps exist yet at G2 — there is nothing to walk per-step).

> G2 explicitly does **NOT** re-run `/review-doc`'s deep soundness / template-alignment pass. Two items, both triage: *is there enough here to review*, and *does it obviously force non-autonomous work*. If the answer to both is yes/no respectively, the design is READY for the review layer to do the deep pass.

### verdict semantics

- **READY** = **ready-for-`/review-doc`** — the design is complete/self-contained enough to be worth a review pass and does not obviously force non-autonomous work; hand it to `/review-doc`.
- **NOT-READY** = a completeness hole makes a review pass unproductive, or the design obviously forces non-autonomous work; emit the **shortest in-scope action list** (e.g., "fill in the Proposed Approach section before review," "resolve the embedded spike in the approach").
- **escalate: re-scope** = the design is too incomplete to triage (a stub, not a draft) — hand back to finish the design before gating.

---

## Tunable slots

### allowed remedy classes

Default — **doc-edit / spike / scope-out / escalate**. No override (G2 uses the base default).

- **doc-edit** — fill a completeness hole in the design in place (add the missing section, define the undefined scope).
- **spike** — if the design forces an unresolved exploration, resolve it before review rather than reviewing around it.
- **scope-out** — defer an out-of-scope sub-area so the design under review is self-contained.
- **escalate** — when the design is a stub, hand back "escalate: re-scope."

---

## Notes

- **Triage, not a second review**: G2's whole identity is *"is this worth a review pass?"* It does not duplicate `/review-doc`'s deep soundness/template-alignment scoring — that runs one step later. Re-scoring here would be the review layer twice.
- **Light autonomy check**: at G2 there are no executable steps, so the autonomy concern is a *smell test* (*"does the approach obviously force non-autonomous work?"*), not G4's per-step verdict. The depth difference is the point — G2 has no steps to walk.
- **No weight slot**: G2 runs **inline** like every gate. Its depth is light because the inputs (a design, not executable steps) make a per-step verdict impossible here — not because of a tunable knob.
- **Bias to READY**: a design that is reviewable but imperfect is **READY** — imperfections are exactly what `/review-doc` exists to catch. Block only on a hole that makes the review pass itself unproductive, or an obvious non-autonomy bake-in.
